# Security

DCC Kiri Manager uses a local administrator account. Create it out of band with `python -m backend.admin`. The command accepts an interactive password or an explicitly managed private stdin stream. Only a scrypt password hash is stored. The web endpoints use signed HttpOnly, SameSite=Strict cookies and digested server-side session IDs. Sessions expire after eight hours and can be revoked on sign-out or password reset. Per-process signing keys expire browser sessions when the application restarts.

- Local HTTP is suitable for a loopback-published port. Configure `KIRI_PANEL_ORIGIN=https://panel.example` for a trusted, explicitly deployed reverse proxy. Preserve the external Host header and strip untrusted proxy headers. This setting enables Secure cookies and HSTS. Keep the origin port bound to loopback.
- Every data endpoint requires a session. Login initiates one, and the session endpoint bootstraps the CSRF token. The liveness response contains only a fixed status. Requests that change state require the exact origin and CSRF token. The app defines no CORS policy for cross-origin access.
- The login gate bounds both verification concurrency and attempts. Response bodies, upstream read deadlines and simultaneous calls are limited. Engine failures return diagnostic codes without upstream payloads.
- The browser selects from administrator-configured `KIRI_SOCKETS` aliases. TCP, DNS, redirects, arbitrary file paths and default Docker socket aliases are outside the connector's transport. Engine requests have a finite allowlist. Dynamic resource keys are validated. Identity is rechecked on each operation, including the socket inode and Kiri Server header.
- A dedicated Kiri socket grants sensitive engine access. The container definition drops all capabilities, uses `no-new-privileges` and a read-only filesystem, and adds only the socket's group when explicitly configured. A read-only bind mount still permits API writes through the socket. Restrict the panel's host and volume to trusted administrators.
- Inventory projections exclude environment variables, commands, raw host paths, arbitrary labels, warning messages and network addresses of connected containers. User-approved log reads are bounded and common secret formats are masked. Application logs omit these lines, but the authorized UI can still render unrecognized secret formats in an application's output.
- The Linux installer is an optional host-side command. It validates a pinned upstream package and uses the operating system's authorization mechanism. The panel itself has no host-shell route and stores no installer credentials.

The app prepares a dedicated volume and a local connection only. A host user with administrative access or a process able to replace the configured socket is inside the trust boundary. If Kiri uses a new identity format, verify its release before changing the connector.
